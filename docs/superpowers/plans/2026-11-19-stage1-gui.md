# Stage 1 GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the runtime drivable from a phone browser: TLS on every LAN listener, a versioned `/api/v1/*` management API, and a `/ui` console — all on the services MCP already uses.

**Architecture:** `runtime-cli` stays the composition root. `run_http_server` builds the domain services once, shares them with `McpServer` and with a new `http_api::ApiState`, and assembles one router through a testable `build_router`. Two listeners share one port number: plain HTTP on loopback, TLS/rustls on each local LAN IPv4. Handlers only authenticate (middleware), validate JSON, and call one service method.

**Tech Stack:** Rust 2021, axum 0.8, axum-server 0.9 (`tls-rustls`), rustls 0.23 pinned to the `ring` provider, rcgen 0.14, tokio, serde; plain ES-module HTML/CSS/JS compiled in with `include_str!`.

**Spec:** `docs/superpowers/specs/2026-11-19-stage1-gui-design.md` (rev 2)

## Global Constraints

- Build gate (every task): `cargo check --workspace --exclude backend-linux --exclude backend-macos --exclude runtime-terminal --exclude backend-windows` and the same excludes for `cargo test --no-fail-fast`.
- `backend-windows` (19 pre-existing errors) and `backend-native::tests::test_native_backend_capabilities_honest` (pre-existing failure) are out of scope; never "fix" them here.
- No new build toolchain: no npm, no bundler, no `rust-embed`. UI assets ship via `include_str!`.
- Loopback stays plain HTTP. Every non-loopback local IPv4 gets TLS. Never bind `0.0.0.0`.
- No absolute host path in any list/detail JSON body. Two documented exceptions only: `ApprovalRequest.resource` and service error text.
- `/api/v1/*` requires a session for every non-loopback peer **even when `remote.pairing_required = false`**; that flag continues to relax `/mcp` only.
- Console mutations do **not** round-trip through `ApprovalBroker`, and **do** write an audit event.
- Reuse the identity model unchanged: ed25519 device keys, 6-digit code with 10-min TTL, 30-minute bearer token. No server-side key generation.
- Never claim unrun behaviour (spec §17). A test that cannot run here is not written as if it passed.

## Review Focus

- A LAN browser with `pairing_required = false` must still get 401 on `/api/v1/workspaces` while `/mcp` stays open — pinned by Task 4 test 4.
- A DHCP address change must regenerate the certificate instead of serving SANs that no longer match — pinned by Task 1.
- `root_id` plus a traversal/absolute `relative_path` must be refused inside discovery/workspace, not by handler string checks — pinned by Task 5.
- Registering the same directory twice (different case, or `\\?\` verbatim on Windows) must return the existing id, not mint a second one — pinned by Task 6.
- Malformed JSON and `/ui/../Cargo.toml` must produce a JSON 400/404, never a panic or a file — pinned by Tasks 4 and 7.

- [ ] **Step 5: Implement `tls.rs`**

Algorithm the tests do not pin:
- `ensure_certificate` returns early iff cert+key parse as PEM **and** metadata exists, is unexpired (`not_after > now + 1 day`), and `current_ips ⊆ meta.san_ips`. Otherwise regenerate (log the reason at `warn!`).
- SAN list = `localhost`, machine hostname (best-effort), `127.0.0.1`, `::1`, plus every `san_ips` entry. `CertificateParams::new(strings)` parses IP strings into IP SANs.
- Write cert/key with `std::fs::write`; on Unix `set_permissions(0o600)` on the key (best effort, `#[cfg(unix)]`).
- Fingerprint = SHA-256 of certificate DER, lowercase hex, `:` between bytes.
- `cert_der` strips `-----BEGIN/END CERTIFICATE-----` and base64-decodes.
- `local_ipv4_addrs`: use `std::net::UdpSocket::connect("8.8.8.8:80")` for the primary address plus `get_if_addrs`-free fallback: if the socket trick fails return `vec![]`; dedupe; skip loopback. (No new crate.)
